# Preview report

The JSON results file accepts the original title, url, sha and status fields, plus optional banner (HTTPS image URL), description, sections and links.

```json
{
  "title": "Shell Workbench",
  "url": "https://preview.example.com/",
  "sha": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
  "status": "success",
  "banner": "https://example.com/preview-ready.svg",
  "description": "Validated preview",
  "sections": [
    {
      "title": "Build",
      "collapsed": true,
      "rows": [
        {"label": "WASM smoke test", "value": "Passed", "status": "success"},
        {"label": "Bundle size", "value": "420 KiB"}
      ]
    }
  ],
  "links": [{"label": "Artifacts", "url": "https://example.com/artifacts"}]
}
```

Statuses: success, failure, pending. Metrics are supplied by the caller, not measured by this action. GitHub controls Markdown styling; arbitrary CSS is not supported. The banner is an external image, not generated by this action. Use trusted HTTPS resources. Existing v1 payloads remain valid.

## Git intelligence

PR totals come from GitHub's pull request API. Commit and file lists are paginated subject to GitHub API limits; displayed lists are capped at 20 commits and 40 files. Directory counts describe retrieved files only. A successful report records its verified SHA; later reports compare against that SHA when available, retaining it on pending or failed reports. The caller should serialize report publication per PR to avoid concurrent comment creation.
