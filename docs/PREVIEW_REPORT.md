# Preview report

The JSON results file accepts the original title, url, sha and status fields, plus optional banner (HTTPS image URL), description, sections and links.

```json
{
  "title": "Shell Workbench",
  "url": "https://preview.example.com/",
  "sha": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
  "status": "success",
  "banner": "https://example.com/preview-ready.svg",
  "description": "Validated preview",
  "sections": [
    {
      "title": "Build",
      "collapsed": true,
      "rows": [
        {"label": "WASM smoke test", "value": "Passed", "status": "success"},
        {"label": "Bundle size", "value": "420 KiB"}
      ]
    }
  ],
  "links": [{"label": "Artifacts", "url": "https://example.com/artifacts"}]
}
```

Statuses: success, failure, pending. Metrics are supplied by the caller, not measured by this action. GitHub controls Markdown styling; arbitrary CSS is not supported. The banner is an external image, not generated by this action. Use trusted HTTPS resources. Existing v1 payloads remain valid.

## Git intelligence

PR totals come from GitHub's pull request API. Commit and file lists are paginated subject to GitHub API limits; displayed lists are capped at 20 commits and 40 files. Directory counts describe retrieved files only. A successful report records its verified SHA; later reports compare against that SHA when available, retaining it on pending or failed reports. The caller should serialize report publication per PR to avoid concurrent comment creation.

## Bundle intelligence

Run `node scripts/measure-bundles.mjs bundle.json dist/app.js dist/style.css` from the consumer workspace (use the script from this repository). Pass `bundle-file: bundle.json` and optionally `baseline-file: baseline.json`. Keep the baseline as a versioned snapshot or artifact; the action does not automatically replace it. Compare identical file scopes and compression settings (gzip level 9, Brotli quality 11). Totals sum independently compressed files, not a compressed archive. Increases are highlighted, not enforced as CI failures.

## Branding and workflow intelligence

`config/projects.json` is the shared project identity catalog. Generate a banner using `node scripts/render-banner.mjs shell 'Preview ready' banner.svg`. Publish the SVG to a trusted HTTPS location and pass its URL as `banner`. The script does not publish assets. Emoji rendering depends on the SVG renderer's installed fonts. Workflow metrics are a snapshot of the current attempt, not final elapsed time: summed completed job durations may overlap. Running steps are excluded. The App needs Actions read permission; unavailable metrics do not block publication.

### Shared banner assets

Regenerate the committed catalog with `node scripts/generate-banners.mjs`. Consumers can use `https://raw.githubusercontent.com/rodkisten/github/main/assets/banners/shell/preview-ready.svg` as the report banner URL. Replace `shell` and `preview-ready` with a catalog project and event slug. Pin a commit instead of `main` for immutable assets. The raw URL is independent of GitHub Pages configuration.
